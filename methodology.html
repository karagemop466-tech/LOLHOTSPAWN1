Methodology, maths and limitations

Written by the pipeline, not by hand, so it always matches the code in scripts/.

1 · What counts as a match

The list of matches is exactly what Hotspawn offers pick'ems for in the League of Legends tab, read from the server-rendered lobby play.hotspawn.com/lol-pickems. Every id is then re-checked against Hotspawn's own fixture feed (/wp-json/wp/v2/fixtures), and the kickoff is verified against the HH:MM UTC stamp on the league page (hotspawn.com/league-of-legends/tournament/<slug>). The lobby only publishes a relative “Locks in” countdown, so a match whose absolute time cannot be cross-checked is flagged rather than published as fact.

2 · Probability from betting lines

Where an external price exists it is always preferred. Decimal odds are converted to raw implied probability (1/odds) and the over-round is removed proportionally (multiplicative de-vig) — a two-way market, since a League of Legends series cannot draw. If two sources price the same fixture their difference is published as a spread. A price is only attached when both team labels match the fixture; if a source page contains several fixtures for the same pair the price is not attached and the row is flagged instead of guessed.

3 · Our own line (model) for matches nobody prices

Formula: p = 1 / (1 + 10 ** -(R_a - R_b) / None) at series level, with ratings produced from verified finished series scorelines only. Parameters: K = None, margin-of-victory factor None, None relaxation passes, shrinkage weight n₀ = None games. 0 finished series were used; 0 rows were dropped for missing/ambiguous scorelines; 0 teams carry a rating.

Confidence bands are sample-size driven, not opinion: high ≥ 6 finished series each and a direct meeting, medium ≥ 6 each, low ≥ 3, very low below that, none when a team has no verifiable result — in which case the row is unresolved, never imputed.

4 · Explicitly excluded

  • Hotspawn's "X% picked" is never an input. It is a crowd poll, published on the cards for comparison only.
  • No odds are read from Hotspawn itself, and no line is invented for a match with no evidence: those rows stay blank and appear under Unresolved picks.
  • No manual entry: the same code path runs on the schedule, so the published snapshot is reproducible from scripts/ alone.

5 · Known limitations

  1. Sub-tier LoL is thinly priced: regional 2nd/3rd divisions, academy and high-school leagues and some emerging-region championships are not on Polymarket and only sporadically on odds-comparison pages. Books that were probed and could not be read programmatically are listed with the exact outcome on the sources ledger.
  2. A form model cannot see roster changes, stand-ins, patch swings, veto order or side preference, which matters most in exactly the leagues where we have to use it.
  3. Ratings are comparable inside a league; cross-league scale relies on shared opponents only and is not calibrated, so tier-to-tier comparisons should be read as soft.
  4. Hotspawn labels many fixtures “Waiting for Information”; if the fixture is never played the pick'em simply voids. Kickoff for those rows can move after this snapshot.
  5. The lobby is weekly (resets with Hotspawn's own reset); matches outside the window are not listed as missing picks.

6 · Reproduce it

pip install -r requirements.txt
python -m scripts.pipeline --out data
python -m scripts.build_site --data data --site site
python -m scripts.verify --data data --site site

Data is collected and rebuilt by GitHub Actions every 6 hours (.github/workflows/refresh.yml) — no manual step. Probabilities come from external betting lines or our own model, never from Hotspawn's pick share.
