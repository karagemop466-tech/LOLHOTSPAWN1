0. Relationship to the Canonical Dashboard

Read this before quoting any number from this site

Two publishers run in this repository and both are served from one GitHub Pages domain. The canonical dashboard (tools/ → repository root, /LOLHOTSPAWN1/, data in data/matches.json) is the pick list: 212 cards Hotspawn lists as status=scheduled, priced from Polymarket, Kalshi with an Elo model over Leaguepedia series results and a publish gate (tools/verify.py) that aborts the commit on any failed check. This companion audit (scripts/ → /docs/, data in data/node/**) re-collects the same feed, fits its own ratings (Leaguepedia and Hotspawn series, tier prior, thin-history shrinkage) and grades recorded picks against official scores. Every card and table row here carries a CANONICAL PICK line with the canonical probability and a deep link, and rows where the two disagree by 5 pp or more — or name opposite winners — are marked DIVERGES and listed on the overview. Where they differ, submit the canonical pick; the gap is published as an audit finding, never averaged away.

Snapshot parity at this build: 199 of 208 scheduled rows appear in the canonical inventory; 9 rows here are not in it; 13 canonical cards are not in this snapshot; 192 rows have a probability on both sides, 11 of them opposite picks (mean |gap| 2.29 pp, max 9.8 pp).

0.1 Series Format Is Not Published by Hotspawn

Hotspawn's fixtures API returns best_of: null for 208 of the 208 scheduled fixtures in this snapshot, so this dashboard renders Bo — rather than a number: an unverified format is left blank per the project's no-inference rule. The rating model still has to assume something, and it treats an unknown format as a single-map series (no best-of amplification), which is the neutral assumption. That assumption is demonstrably wrong for at least one fixture: Leaguepedia's official Data:LCP/2027 Season/Promotion wikitext opens its FFA Round 1 MatchSchedule/Start block with the parameters tab=FFA Round 1 | bestof=5 | shownname=LCP 2027 Promotion for the fixture team1=FENNEL | team2=Nothin'Here on 2026-11-10 05:00 UTC — Hotspawn card #1081421 (LCP 2027 Promotion), which this snapshot renders as Bo —: a Bo5, not a Bo1. Format-sensitive probabilities for that fixture (and any other Leaguepedia Bo3/Bo5 card Hotspawn leaves null) are therefore understated in amplitude, in this view and in the canonical one, until a verified format source is joined.

1. Strict Independence from Hotspawn Signals

Hotspawn's public API exposes participants0_picked_percent, participants1_picked_percent, offered_points, and tier. Zero Hotspawn crowd or gamification fields are ever read by any probability, consensus, or rating function in scripts/analyze.mjs. Every published win probability derives solely from external real-money markets or external historical match outcomes.

3. Self-Originated Pre-Kickoff Elo / Bradley-Terry Model

  • Dataset: 32,568 completed non-forfeit Leaguepedia + Hotspawn LoL series replayed in strict chronological order; administrative forfeits (ff) are excluded from skill updates.
  • Zero look-ahead: Every Hotspawn fixture at timestamp T is scored exclusively from ratings accumulated across matches with t < T.
  • Competition-scoped entity disambiguation: Teams are resolved inside their specific Leaguepedia tournament page before global matching, preventing cross-region homonym contamination (such as Bulgarian amateur PNG vs Brazilian paiN Gaming on #1083097, or Swiss PvB (Swiss Team) vs Vietnamese Phong Vũ Buffalo on #1079031).
  • Empirical-Bayes shrinkage & series transform: Ratings initialize at 1500 with dynamic K = 38 / 28 / 22, shrink toward 1500 via n / (n + 6), and map to Bo3/Bo5 series probabilities with correlated-game damping (α = 0.72). Full current ratings JSON: data/node/model/ratings.json ↗.
